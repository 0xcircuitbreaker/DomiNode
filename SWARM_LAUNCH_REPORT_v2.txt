7. IP POOL ANALYSIS: 250 DC IPs vs RESIDENTIAL vs 1K IPs
================================================================================

*** THIS IS THE KEY SECTION ***

--- How Your DC IPs Work ---

Mode: Gateway (rotating DC via p.webshare.io)
- All requests go through p.webshare.io:80
- Webshare automatically rotates across YOUR 250-IP pool
- Each request gets a random IP unless sticky session is used
- Append "-rotate" to username for per-request rotation (default)
- Append "-session-XXXXX" for sticky (same IP for duration)

Your 250 IPs are SHARED datacenter IPs — meaning:
- Other Webshare customers may share the same IPs
- Bad behavior by others can burn IPs in your pool
- IPs are from known datacenter ranges (detectable)

--- 250 DC IPs: Enough for the Swarm? ---

Scenario: 200 agents, each making 80 requests/day

Concurrent agents at any moment:
- With 5-second delay between requests: ~200 concurrent connections
- 200 agents / 250 IPs = 0.8 agents per IP
- Each IP handles ~64 requests/day (200 agents x 80 req / 250 IPs)

Target-specific analysis:

9. AGENT LIFECYCLE
================================================================================

POSTER BOT (DC):
1. Register: POST /api/auth/register
2. Create API key: POST /api/keys
3. Open CONNECT tunnel: dc-country-US:{api_key}@proxy:8080
4. POST to Moltbook/X/social via persistent tunnel
5. Content: "Used @DomiNode for 50 proxied requests, $0 cost, agent-native"
6. Repeat every few hours

SCRAPER BOT (Residential):
1. Register: POST /api/auth/register
2. Create API key: POST /api/keys
3. Open CONNECT tunnel: residential-country-US:{api_key}@proxy:8080
4. Search Google for jobs, scrape listings
5. Feed results to poster bots or store for analysis
6. Repeat (budget ~5MB residential/day)

10. HARD-WAVE DEPLOYMENT

Scripts: scripts/swarm-launch.sh + scripts/swarm-agent.sh

Quick start:
  # Launch 100 DC poster agents
  SWARM_TARGETS="https://httpbin.org/ip,https://httpbin.org/get" \
  SWARM_MAX_REQUESTS=50 \
  SWARM_DELAY_SEC=3 \
  ./scripts/swarm-launch.sh 100 http://localhost:3000 localhost 8080

With Moltbook posting:
  SWARM_POST_URL="https://api.moltbook.com/v1/posts" \
  SWARM_POST_TOKEN="your_moltbook_token" \
  ./scripts/swarm-launch.sh 200 http://localhost:3000 localhost 8080

The launcher:
- Batches 25 agents at a time (SWARM_BATCH_SIZE)
- 10 second delay between batches (SWARM_BATCH_DELAY)
- Each agent: register -> login -> API key -> scrape -> post
- All traffic routed through DomiNode proxy (dogfooding)
- Logs to /tmp/dominusnode-swarm/agent-*.log
- PIDs saved for easy kill-all

Bandwidth per wave:
  100 agents x 50 requests x 100KB = ~500 MB DC (0.05% of 1TB)
  Can run this daily for months without concern.
