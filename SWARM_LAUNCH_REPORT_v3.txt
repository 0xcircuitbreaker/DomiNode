## Architecture Change: Team-Based Swarm Model

Previous model (v2):
  - Each agent registers its own account (200 accounts)
  - Each uses personal plan + personal API key
  - All scrapes via residential proxy (2.5MB/agent/run)
  - 200 agents x 2.5MB x 30 days = 15GB/month (60% of 25GB cap)

New model (v3):
  - 1 main agent creates a team ("DomiNode Agent Swarm")
  - Admin credits team wallet once ($100)
  - Main agent creates N team API keys (1 per sub-agent)
  - Sub-agents use team keys — no registration needed
  - Team plan (payg) gives unrestricted pool access
  - Smart routing: residential ONLY for Google/LinkedIn, DC for everything else
  - Only 1 user account needed (the main agent), N API keys

## Bugs Fixed

1. allowedProxyTypes='all' broke DC access
   - 'all' is truthy, so `if (plan.allowedProxyTypes)` entered the restriction block
   - "dc" !== "all" → rejected DC requests for swarm-mixed and payg plans
   - "all" passed as proxyType to provider selector → no matching provider
   - FIX: Added `&& plan.allowedProxyTypes !== 'all'` guard in 4 locations:
     - session-manager.ts (startSession)
     - server.ts (HTTP handler)
     - server.ts (CONNECT handler)
     - socks5.ts (SOCKS5 handler)

2. Team API keys used creator's personal plan instead of team plan
   - Team API keys carry teamId, but proxy gateway fetched getUserPlan(userId)
   - If creator has free-dc plan, team keys were restricted to DC only
   - FIX: Added getTeamPlan(teamId) to plan-repo.ts
   - FIX: Proxy gateway now checks: teamId ? getTeamPlan(teamId) : getUserPlan(userId)
   - Applied in 3 locations: HTTP handler, CONNECT handler, SOCKS5 handler

3. New: admin plan-assign endpoint
   - PUT /api/admin/users/:id/plan — assign any plan to a user
   - Useful for assigning swarm-mixed plan to agents using personal keys

## Residential Bandwidth Conservation

Strategy: Smart per-request pool routing in swarm-agent.sh

  Residential (expensive, $5/GB): ONLY for sites that block DC IPs
    - google.com, linkedin.com, indeed.com, glassdoor.com

  DC (cheap, $3/GB): Everything else
    - httpbin.org, social API posts, health checks, testing

  Per agent per run:
    - 1 residential request per cycle x 5 cycles = 5 residential requests
    - 4 DC requests per cycle x 5 cycles = 20 DC requests
    - ~0.5MB residential per agent per run (down from 2.5MB)

  Budget at 200 agents, daily runs:
    Old:  2.5MB x 200 x 30 = 15,000 MB/month = 15 GB (60% of 25GB cap)
    New:  0.5MB x 200 x 30 =  3,000 MB/month =  3 GB (12% of 25GB cap)
    Savings: 12 GB/month residential bandwidth freed for paying customers

  DC budget (no cap concern):
    0.5MB x 200 x 30 = 3 GB/month (0.3% of 1TB cap)

## How to Run

  1. Start services:
     docker compose up -d
     npm run db:migrate
     npm run build
     npm run start:api &
     npm run start:proxy &

  2. Launch swarm:
     ADMIN_PASSWORD=<your-admin-password> \
     SWARM_POST_URLS=https://moltbook.example/api/posts \
     SWARM_POST_TOKENS=<moltbook-token> \
     ./scripts/swarm-launch.sh 200

  The launcher will:
     a) Authenticate as admin
     b) Launch main agent
     c) Main agent creates team + credits wallet + creates 200 team keys
     d) 200 sub-agents launch in batches of 25
     e) Each sub-agent: 1 residential + 4 DC requests per cycle, 5 cycles
     f) Total: ~3GB residential/month, ~3GB DC/month
